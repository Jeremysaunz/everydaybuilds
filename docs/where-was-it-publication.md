# 물건찾기지도 두 번째 글 반영 — 2026-10-15

## 반영 범위

- 한국어: `/ko/builds/where-was-it`
- 영어: `/en/builds/where-was-it`
- 한국어 시작 앱: `/tools/where-was-it.html`
- 영어 시작 앱: `/tools/where-was-it-en.html`
- 홈·글 목록·RSS에서 같은 수정일이면 두 번째 글을 먼저 표시한다. 사이트맵에 두 글 주소와 두 앱 주소를 추가했다.
- 두 글 모두 언어에 맞는 앱 열기·HTML 다운로드·다른 언어 글로 연결한다. 첫 카페 글과 서로 연결한다.

## 원고와 이미지

한국어 원문은 문장을 바꾸지 않았다. 기존 파일 경로를 새 상대경로로 바꾸고 첫 카페 글에 링크만 추가한 결과임을 원본과 대조했다. 영어 원고는 같은 요청·변화·확인 범위를 유지하며 제작 시간, 가족 반응이나 사용 효과를 추가하지 않았다.

한국어 본문 세 장은 기존 실제 제작 화면을 유지한다. 파일명은 PNG였지만 실제 데이터는 JPEG이므로 공개용 복사본을 JPEG 확장자로 연결했다. 이미지 내용은 바꾸지 않았다.

영어 첫 이미지는 보관한 단일 공간 버전을 번역해 실제 실행하고 다시 캡처했다. 영어 단어가 잘리지 않도록 툴팁 폭만 조정했다. 현재 영어 앱에서 검색 결과와 찾기 놀이 화면을 각각 캡처했으며, 두 언어 대표 이미지도 직접 캡처했다. 영어 글 캡션에 과거 버전 재캡처와 현재 화면을 구분했다. 사진은 샘플 수납장 그림이며 실제 집 사진이나 가족 사용 장면으로 설명하지 않는다.

## 다국어 앱

두 파일 모두 한국어·영어 UI와 동일한 내장 캐릭터를 포함한다. 원래 IndexedDB `everyday-finds-house`와 로컬 저장 키 `everyday-finds-house-v2`, 이전 단일 지도 키 `everyday-finds-map-v1`을 유지한다.

언어를 바꾸면 변경하지 않은 기본 샘플 문구만 번역하고, 직접 입력한 공간·물건 이름·메모와 사진은 유지한다. 현재 검색어, 선택한 물건, 위치 표시, 찾기 놀이의 문제·힌트·오답·진행을 보존한다. 사진과 물건 정보는 서버로 전송하지 않으며 개인정보 안내에도 실제 저장 방식을 반영했다.

## 확인 결과

- 원본 제품과 사이트 반영 파일 일치 검사 통과. 현재 로컬 파일 링크 45개와 공개 JPEG 8개 검사 통과.
- `node site/scripts/verify-object-map.mjs`: 두 파일 구문·독립성·저장 키, 샘플·놀이 문구 왕복 번역, 개인 입력·사진 보존, 두 언어의 v1/v2 백업 호환 통과.
- `node site/scripts/verify-cafe-game.mjs`: 기존 카페 게임 다국어·진행 상태 검사 통과.
- 실제 브라우저의 별도 테스트 출처에서 charger 검색 → 위치 선택, 새 공간 → 사진 추가 → 개인 물건·별칭·메모 등록 → 한영 왕복 → 새로고침 → 별칭 검색 → 백업 내용 확인을 완료했다.
- 찾기 놀이 다섯 문제를 실제로 풀어 완료했다. 도중에 오답 한 번과 힌트 한 번을 사용한 뒤 언어를 왕복해 문제·문구·힌트·진행이 유지되는 것을 확인했다.
- 실제 CSS 폭 320px에서 한영 지도 문서의 가로 넘침 없음. 공간 카드 갤러리는 내부에서 가로로 스크롤한다. 글은 288px에서도 한영 문서의 가로 넘침이 없음을 확인했다. 화면 크기 설정은 원래대로 되돌렸다.
- 블로그 영어 이미지 세 장 실제 로딩, 목차 이동, 홈의 새 글 우선 표시 확인. 브라우저 콘솔 오류 없음.
- `npm run lint`, `npx tsc --noEmit`, `npm run build -- --webpack` 통과. 새 두 언어 글을 포함해 정적 페이지 22개 생성.
- `verify-seo.mjs`: 16개 한영 페이지, 새 이미지·다운로드 연결, 메타데이터·구조화 데이터·RSS·사이트맵 20개 주소·404 검사 통과.

커밋·푸시·공개 배포는 하지 않았다. 확인은 로컬 반영과 도구 작동 범위이며 가족의 실제 사용이나 학습 효과를 입증하지 않는다.

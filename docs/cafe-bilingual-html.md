# 카페 첫날 다국어 HTML

2026-10-12: 별도 단일 언어 파일 두 개를, 각 파일 안에서 한국어와 영어를 전환할 수 있는 형태로 변경했다.

- `/tools/cafe-first-day.html`: 한국어로 시작한다.
- `/tools/cafe-first-day-en.html`: 영어로 시작한다.
- 두 다운로드 파일 모두 두 언어의 화면·교육 내용·게임 코드를 포함한다. 전환 시 다른 파일이나 번역 서버에 요청하지 않는다. 외부 실행 스크립트, 폰트, 이미지 의존성이 없다. 교육 참고 링크는 사용자가 눌렀을 때만 외부 사이트를 연다.
- 상단의 `한국어 / English` 버튼을 사용한다. 선택한 언어는 `#lang=ko` 또는 `#lang=en`으로 표시되어 새로고침 후에도 유지된다.
- 실습 단계, 제조 컵, 점수, 퀴즈 답변, 체크리스트, 메뉴 선택, 검색어와 작성 중인 레시피를 전환 시 유지한다. 미저장 레시피 초안은 언어 전환 시 메모리에서만 옮기며, 새로고침 전에 저장해야 한다.
- 내장 예시 이름과 제조 단계, 계량 단위는 번역한다. 직접 입력한 이름·메모·재료 이름·제조 단계는 그대로 둔다. 한국어로 작성한 레시피를 영어 화면에서 실행할 수도 있다.
- 새 공통 상태는 `cafe-first-day-bilingual-v1`, 언어별 작업 데이터는 `cafe-first-day-i18n-ko-*`와 `cafe-first-day-i18n-en-*`에 저장한다. 기존 저장 키는 읽어서 최초 상태를 가져오고 덮어쓰지 않는다. 기존 두 언어의 기록을 자동으로 합산하지 않는다. 최초로 연 파일의 상태에서 시작한다.
- 저장은 같은 브라우저·출처에 한정한다. 다른 기기, 브라우저, 파일 경로 사이의 자동 동기화는 제공하지 않는다. 브라우저가 파일의 저장소를 제한하더라도 화면 내 언어 전환은 동작한다. 레시피는 JSON으로 백업할 수 있다.

## 원본과 생성

전달받은 한국어 원본은 `content/tools/cafe-first-day.ko.html`에 그대로 보존했다. 이 원본과 번역 사전 `content/tools/cafe-first-day.en.json`, 전환 코드 `scripts/cafe-game-*.js.txt`를 읽어 `python3 scripts/localize-cafe-game.py`로 공개 파일 두 개를 생성한다. 공개 HTML을 직접 수정하면 다음 생성 때 덮어써지므로 원본 또는 생성 코드를 수정한다.

기존 게시글의 캡처는 당시 화면이다. 새 언어 전환 버튼을 과거 캡처에 추가하지 않았다.

## 확인

- `node scripts/verify-cafe-game.mjs`: 생성된 두 파일의 JavaScript 구문, 외부 실행 자원 의존성, 두 언어 포함 여부, 상태 왕복 보존, 두 언어 레시피의 재료 판별을 검사한다.
- 로컬 브라우저: 영어로 연습 시작 → 얼음 추가 → 한국어 전환 → 물 추가 → 영어 전환 → 새로고침 → 나머지 제조·제공 → 한국어 결과 100점 유지.
- 레시피 편집: 미저장 사용자 이름·메모·재료·수량을 입력하고 영어로 전환해 보존 확인. 단위 `샷`은 `shots`로 전환하고 저장 확인.
- 기본기: 퀴즈 답변과 현장 체크 후 영어로 전환해 같은 질문·답변·체크 상태 유지 확인.
- 모바일: 실제 CSS 폭 320px에서 한국어와 영어 설정 화면을 확인했다. 두 화면 모두 문서 폭 320px로 가로 넘침이 없고 언어 버튼이 화면 안에 표시된다. 테스트 후 화면 크기 설정을 원래대로 되돌렸다.
- 원본 보존: 보관한 한국어 원본을 전달받은 원본 파일과 바이트 단위로 대조해 일치 확인.
- 블로그 다운로드: 영어 글의 두 다운로드 링크가 새 영어 기본 파일을 가리킴을 확인했다. 두 HTML 주소 모두 HTTP 200이며 실제 응답이 생성한 파일과 바이트 단위로 일치한다. 브라우저의 다운로드 완료 이벤트 확인은 도구 시간 초과로 완료하지 못했다.
- 단독 `file://` 열기는 브라우저 자동화 도구의 URL 정책에서 지원하지 않는다. 파일의 독립성은 생성 파일 검사로 확인했고, 실제 화면 동작은 로컬 HTTP 주소에서 확인했다.
